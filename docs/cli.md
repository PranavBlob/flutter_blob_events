# Event SDK CLI

Package: `packages/event_sdk_cli`  
Executable: `event_sdk` (alias: `event_sdk_cli`)

This is the primary integration path. It selects platform packages, updates
`pubspec.yaml`, and creates the app-owned setup/config files.

## Install the CLI once

```bash
dart pub global activate --source git \
  https://github.com/PranavBlob/flutter_blob_events.git \
  --git-path packages/event_sdk_cli \
  --git-ref event_sdk
```

Ensure Dart's global executable directory is on your `PATH` if prompted by Dart.

## Integrate an app

From the Flutter app root:

```bash
event_sdk init --platforms aws,adjust
```

That command:

1. Adds `event_sdk`, `event_sdk_aws`, and `event_sdk_adjust` git dependencies
2. Creates `lib/generated/event_sdk_setup.g.dart`
3. Creates **your editable** `lib/event_sdk_config.dart`
4. Updates native host app requirements:
   - Android: adds `android.permission.INTERNET`
   - iOS (when `adjust` is enabled): adds `NSUserTrackingUsageDescription`

Fill your vendor credentials in `lib/event_sdk_config.dart`, including
`eventSdkDefaultParams` (sent to all platforms). Then call
`await setupEventSdk()` before `runApp()`. Credentials cannot be generated by
the CLI because they belong to your AWS, Adjust, Firebase, and Amplitude accounts.

After `init` (or `add` / `remove`), run:

```bash
flutter pub get
```

## Commands

### `list`

```bash
event_sdk list
```

Shows supported platforms and which ones look enabled in the current app (from generated setup).

### `init`

```bash
event_sdk init --platforms aws,adjust \
  --git-url https://github.com/PranavBlob/flutter_blob_events.git \
  --ref event_sdk
```

| Flag | Default | Meaning |
|---|---|---|
| `--platforms` / `-p` | (required) | Comma-separated: `aws`, `aws_endpoint`, `adjust`, … |
| `--git-url` | `https://github.com/PranavBlob/flutter_blob_events.git` | Monorepo git URL |
| `--ref` | `event_sdk` | Branch / tag / commit |

Creates / updates:

- Git deps in `pubspec.yaml` for `event_sdk` + selected platforms
- generated entrypoint: `lib/generated/event_sdk_setup.g.dart`
- app-owned credentials/config: `lib/event_sdk_config.dart`
- native host app requirements (Android/iOS)

### `add`

```bash
event_sdk add --platforms firebase,amplitude
```

Merges new platforms into existing setup.  
`firebase`, `amplitude`, and `aws_endpoint` are available and can be added to
an existing integration. Initialize Firebase in the host app before
`setupEventSdk()`, then replace generated credential placeholders.

After `add`, run:

```bash
flutter pub get
```

### `remove`

```bash
event_sdk remove --platforms adjust
```

Removes platform deps and regenerates setup. Refuses to remove the last platform.

After `remove`, run:

```bash
flutter pub get
```

### `doctor`

```bash
event_sdk doctor
```

Checks that the setup/config files exist, flags unfilled credential placeholders,
and verifies native host requirements:
- Android INTERNET permission (if any analytics platform is enabled)
- iOS `NSUserTrackingUsageDescription` when `adjust` is enabled

It also reminds you to initialize Firebase when Firebase is selected.

## Generated setup vs app-owned config

The CLI owns and safely regenerates:

```text
lib/generated/event_sdk_setup.g.dart
```

It creates once, then preserves your edits in:

```text
lib/event_sdk_config.dart
```

Replace the TODO credential values there. The generated entrypoint stays small:

```dart
Future<void> setupEventSdk() async {
  await EventSdk.init(
    createEventSdkAdapters(),
    config: createEventSdkConfig(),
  );
}
```

Edit default params (sent to **all** platforms) in `lib/event_sdk_config.dart`:

```dart
final eventSdkDefaultParams = <String, Object?>{
  'source': 'mobile_app',
  'env': 'dev',
};
```

Change them at runtime with `EventSdk.setDefaultParam('userId', 'user_123')`.
